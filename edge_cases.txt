EDGE CASES / SAFETY CASES / MINOR LOGICS (FIRE PIPELINE)

1. geo position & routing:
    - nearest location office
    bonus:
    - route to office
    - cost of travel to the locations, Dijkstra algorithm
        - if outside of country client, use google maps api
        - if inside of country client, use openrouteservice api
        - for inside of country client: conisder time, quality of road, traffic and overall cost

2. chat with user to manager:
    - if the priority is low, possible online solution with/without online chat in UI

3. Several managers per city:
    - allocate client by: 
        - segment
        - priority
        - manager's current load
    - allocate free manager to online solution

4. INGESTION / DATA QUALITY

    - Missing required CSV columns or wrong types:
        - reject batch or mark rows as invalid; log clear error.
    - Duplicate ticket_id:
        - idempotent upsert (keep latest/first by rule); log duplicate_ticket_id.
    - Broken joins (ticket references missing manager/office keys), null IDs:
        - mark ticket needs_data_fix; do not route until fixed.
    - Corrupted row / encoding issues:
        - skip row + log row number; continue processing remaining rows (partial success).

5. AI ENRICHMENT (LLM ROBUSTNESS)

    - LLM timeout / unavailable:
        - fallback analytics; set ai_fallback=true.
        - Defaults example: language=RU, sentiment=Neutral, priority=5, type=Consultation (or App Failure), generic summary.
    - Invalid JSON / schema mismatch from LLM:
        - validate + retry once; if still invalid -> fallback analytics; log ai_schema_error.
    - Ambiguous language:
        - set RU by default; set language_confidence=low.
    - Empty text + missing attachment:
        - needs_clarification flag; lower priority (e.g., 3–4); route to general queue.
    - Prompt injection / malicious instructions inside ticket text:
        - hard-validate enums and numeric ranges; ignore ticket instructions; never allow ticket text to override routing rules.

6. GEO / OFFICE SELECTION

    - Unknown address / cannot geocode:
        - spec fallback 50/50 split Astana vs Almaty (use deterministic hash(ticket_id)%2).
    - Address outside Kazakhstan (abroad):
        - same 50/50 fallback.
    - Tie in nearest office distance:
        - deterministic tie-break (lowest office_id or alphabetical office name).
    - Missing office coordinates:
        - exclude that office from distance calc; if all missing -> 50/50 fallback.

7. ELIGIBILITY FILTERING (HARD RULES)

    - No eligible managers after applying VIP/Chief/KZ/ENG constraints:
        - do NOT relax hard rules; put into escalation/unassigned queue; log no_eligible_manager with reason list.
    - Manager skill fields missing/null:
        - treat as skill absent (conservative).
    - Manager inactive / on leave (if supported):
        - exclude from candidates (requires is_active flag or config list).
    - VIP segment but zero VIP-skilled managers:
        - escalation/unassigned; do not assign to non-VIP.

8. LOAD BALANCING + ROUND ROBIN CORRECTNESS

    - More than 2 managers share minimal load:
        - pick two deterministically (sort by load, then manager_id).
    - Invalid load values (missing/negative):
        - coerce to large value or exclude; log invalid_load.
    - RR state missing (first run):
        - initialize pointer deterministically (e.g., 0).
    - Concurrency (simultaneous assignments):
        - DB transaction + row-level lock on rr_state to ensure atomic RR updates.

9. OPERATIONAL SAFETY / AUDITABILITY

    - SLA <= 10 seconds risk:
        - cache AI enrichment per ticket; timebox LLM call; fallback on timeout; avoid repeated LLM calls on UI refresh.
    - Full traceability requirement:
        - store routing_trace in DB (geo decision, applied filters, candidate loads, RR pointer, assigned manager).
    - PII handling:
        - avoid logging raw addresses; store normalized address + geo coords; redact in UI logs if needed.

DETERMINISTIC “MINOR” RULES (IMPORTANT FOR JUDGES)

    - Stable ordering/tie-breaks (office_id, manager_id).
    - Deterministic 50/50 fallback using hash(ticket_id).
    - Strict schema validation for LLM outputs (enums + priority 1–10).
    - Explicit “unassigned/escalation” state (never silent failure).
    - Single source of truth for routing rules (central routing module).


Update: 
# Production-Level Edge, Safety, and Exception Cases for the F.I.R.E. Service

This checklist extends the current pipeline edge-case coverage (ingestion validation, DeadLetter routing, idempotency, fallback flags, etc.).

---

## 1) API + Platform Reliability

- **Rate limiting (HTTP 429)**
  - Respect `Retry-After` if present.
  - Exponential backoff + jitter; cap retries; avoid thundering herd.
- **Timeouts and transient failures**
  - Differentiate: timeout vs 5xx vs network errors.
  - Retry only retryable classes; fail fast on non-retryable errors.
- **Degraded mode**
  - If LLM/API is down or failing above threshold:
    - skip enrichment
    - route using deterministic rules/defaults
    - mark `degraded_mode=true` + `ai_fallback=true`
    - display status banner in UI.
- **Duplicate submissions beyond ticket_id**
  - UI double-click / refresh replay; enforce request-level idempotency:
    - idempotency key header OR request hash
    - return prior result without re-processing.
- **Queue overload / backpressure**
  - Hard caps: max CSV rows, max description length, max jobs per user/org.
  - Reject gracefully instead of memory blowups; provide clear error message.
- **Poison-pill tickets**
  - If a ticket repeatedly fails: quarantine to DeadLetter with `do_not_retry=true`.

---

## 2) Security & Abuse Resistance

- **Authentication + Authorization (RBAC)**
  - Separate roles: upload bulk, view PII, view traces, manual reassign, admin.
- **DoS / abuse controls**
  - Rate limit per user/org; cap concurrency; cap batch size.
  - Limit request size and enforce server-side limits (not only UI).
- **Prompt injection / exfiltration attempts**
  - Detect patterns like “ignore previous instructions”, “print system prompt”.
  - Set `prompt_injection_attempt=true`, block sensitive outputs, log incident.
- **PII leakage prevention**
  - Redact phone/email/address from logs.
  - Store raw text in DB with strict access; mask in UI by default.
- **Secrets hygiene**
  - API keys only in env/vault; never in logs.
  - Rotation policy + access audit.
- **SSRF / URL/attachment risks (if added later)**
  - Block private IP ranges; enforce allowlist; scan file types; size limits.

---

## 3) Data Quality & Input Corner Cases

- **Encoding / Unicode normalization**
  - Normalize Unicode; trim; collapse whitespace.
  - Handle Cyrillic/Latin lookalikes; normalize “Алматы/Almaty/Alma-Ata”.
- **CSV injection**
  - Sanitize cells starting with `=`, `+`, `-`, `@` to prevent spreadsheet formula execution on export.
- **Non-unique GUID semantics**
  - Define whether `GUID клиента` can have multiple tickets.
  - If yes: ensure unique `ticket_id` is separate from `GUID клиента`.
- **Outliers**
  - Extremely long descriptions; repeated characters; garbage text; emojis-only.
  - Early exit → `needs_clarification=true` without calling the LLM.

---

## 4) LLM (DeepSeek API) Robustness & Output Safety

- **Schema-valid but wrong content**
  - Add semantic sanity checks:
    - empty/garbage input → `needs_clarification=true`
    - priority bounds and guardrails
    - type must be one of the allowed enums (reject otherwise).
- **Hallucinated fields**
  - Require short `*_rationale` or `evidence` snippets (<= 20 words) per critical field.
  - Reject or lower confidence if rationale is missing or contradicts text.
- **Toxic/unsafe summary output**
  - Filter slurs/threats; replace with safe template; set `content_filtered=true`.
- **Cross-tenant leakage**
  - Never include other customers’ data or internal lists in prompts.
  - Ensure each call is stateless (no “conversation carryover”).
- **Model/prompt drift**
  - Version everything: `model_id`, `prompt_version`, temperature, max_tokens.
  - Monitor distribution drift (Type/Priority/Language) and alert on spikes.

---

## 5) Geo-Routing & Address Resolution Edge Cases

- **Ambiguous places**
  - Names that are also people/regions (e.g., “Абай”); require `address_confidence`.
- **Border/country ambiguity**
  - Shared city names across countries; enforce KZ-only routing logic + `foreign_country=true`.
- **Office metadata quality**
  - Validate at startup:
    - missing lat/lon
    - swapped coordinates
    - duplicate office entries
    - inconsistent region tags.
- **Geocode failures**
  - Deterministic fallback path; cache failures to avoid repeated cost.

---

## 6) Manager Eligibility & Assignment Fairness

- **Stale load data**
  - Define refresh/TTL; if stale set `load_stale=true`.
- **Starvation**
  - If tie-break is always `(load, manager_id)`, some managers may never be selected.
  - Rotate tie-break seed periodically (e.g., daily) while staying deterministic.
- **Reassignment loops**
  - Keep assignment history; cap reassignment count; require reason code.
- **After-hours / holidays**
  - Separate pool or “duty manager” logic; handle local holidays and business hours.

---

## 7) Concurrency & Transactional Integrity

- **At-least-once processing (queues)**
  - Assume duplicates; make assignment idempotent:
    - unique constraint on `(ticket_id, assignment_version)` or equivalent.
- **Deadlocks**
  - Define lock ordering (RR state row vs ticket row) and keep transactions minimal.
- **Race with manager availability**
  - Re-check `active` status inside the assignment transaction.

---

## 8) Observability, SLOs, and Incident Readiness

- **Correlation propagation**
  - Ensure `correlation_id` is in every log line and DB record.
- **Key metrics**
  - p50/p95/p99 latency per stage
  - LLM schema error rate
  - fallback rate (`ai_fallback`)
  - deadletter rate
  - VIP unassigned count
  - 429/5xx rates
  - token usage and cost estimates.
- **Alerting**
  - Alerts on: fallback spikes, schema error spikes, deadletter spikes, p95 latency breach, VIP unassigned > threshold.
- **Runbooks**
  - Examples:
    - “429 spike → reduce concurrency, increase backoff”
    - “schema errors → roll back prompt_version”
    - “routing drift → enable shadow evaluation and compare”

---

## 9) Compliance & Retention

- **Retention policy**
  - TTL for raw text; separate retention for audit traces.
- **Access auditing**
  - Log who viewed/exported PII and routing traces; immutable audit trail.
- **Deletion workflow**
  - If required: implement “right to delete” flow with audit-safe tombstones.

---

## Minimal Production Checklist (High Signal)
- Deterministic failure modes and explicit status flags
- Idempotency across ingestion, enrichment, and assignment
- Strict input + LLM output validation
- Rate limits + circuit breaker + degraded mode
- Redaction + RBAC + audit logs
- Alerting on fallback, schema errors, deadletters, VIP unassigned, p95 latency
